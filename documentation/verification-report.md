## 3. Comparative Audit: AI-Generated Answers vs. Verified Canonical Answers

During the development of the curriculum, candidate explanations and code samples generated by Large Language Models (ChatGPT, Claude, Gemini, DeepSeek) were evaluated against GNU Coreutils documentation and Linux manual pages.

### Audit Item 1: The Behavior of `rm --preserve-root`
* **Raw AI-Generated Output:**  
  *"Modern Linux distros will always protect you from `rm -rf /` because of the built-in preserve-root flag, so running destructive wildcard commands is no longer dangerous."*
* **Canonical Manual Check (GNU Coreutils Manual §11.1):**  
  GNU `rm` enables `--preserve-root` by default, which rejects `rm -rf /`. However, when a student types `rm -rf /*`, the Bash shell performs filename expansion (globbing) *before* passing arguments to `rm`. The arguments become `/bin /etc /home /usr ...`. Because none of these individual paths are `/` itself, the safeguard **does not trigger**, and the entire system is deleted!
* **Correction Made:** Explicitly refuted the AI claim in both the curriculum and the Safety Center. Instructed students never to rely on `--preserve-root` when wildcards are present.

### Audit Item 2: File Deletion vs. File Write Permissions
* **Raw AI-Generated Output:**  
  *"If you set `chmod 444 document.txt`, the file cannot be deleted by anyone except root."*
* **Canonical Manual Check (POSIX.1-2017 §2.3 & Linux `unlink(2)`):**  
  File deletion is a modification of the *directory's* contents, not the file's contents. If a user possesses write (`w`) permission on the enclosing directory, they can delete any file within it, even if the file itself is mode `000` (read-only or no-access). `rm` merely issues a confirmation prompt (`rm: remove write-protected regular empty file ...?`), but typing `y` unlinks the file permanently.
* **Correction Made:** Added a dedicated lesson in Module 6 (File Permissions) clarifying the distinction between directory write permissions and file write permissions.

### Audit Item 3: Deprecated Networking Utilities
* **Raw AI-Generated Output:**  
  *"To check your IP address, run `ifconfig` and to view open network ports, run `netstat -tuln`."*
* **Canonical Manual Check (Ubuntu & Debian Deprecation Notices):**  
  `net-tools` (which includes `ifconfig` and `netstat`) was deprecated in 2009 and is not installed by default on modern Ubuntu, Debian, or Red Hat distributions. Modern systems use the `iproute2` suite (`ip addr`, `ss -tuln`).
* **Correction Made:** Replaced all outdated networking commands with modern `ip` and `ss` commands in the advanced curriculum.

## 6. Project Limitations & Identified Future Work

To uphold honest academic standards, the following technical limitations of the current implementation are explicitly acknowledged:

1. **In-Browser Terminal Emulation Scope:**
   * The web terminal runs a client-side virtual filesystem implemented in JavaScript.
   * It accurately simulates command inputs, outputs, directory state changes, and permission strings for educational commands (`ls`, `cd`, `pwd`, `mkdir`, `touch`, `rm`, `cat`, `grep`, `chmod`, `whoami`, `date`, `history`).
   * *Limitation:* It does not emulate real Linux kernel system calls (`ioctl`), multi-threading, networking sockets, or real hardware block devices (`/dev/sda`).
2. **Offline Rule-Based AI Engine:**
   * To satisfy the zero-cost requirement without requiring students to register paid API keys (OpenAI / Google Cloud), the built-in AI Learning Assistant uses a deterministic, rule-based natural language pattern matcher.
   * *Limitation:* While exceptionally fast, completely private, and immune to server downtime, it cannot generate creative explanations for arbitrary edge-case commands outside its extensive reference knowledge base.
3. **Pending Tests to Be Performed by Faculty / Students:**
   * [ ] Execution of `linux-learning-demo.sh` across non-Debian distributions (Fedora 40, Arch Linux).
   * [ ] Accessibility audit using screen-reader software (NVDA / VoiceOver) across all dashboard modules.
